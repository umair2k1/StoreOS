# StoreOS Cloud — Decisions and open questions (review v2)

Numbered so prompts can cite them (`DECISIONS D-04`). "Decided" items are already applied in the prompts. "Open" items need a human.

## Decided (applied in the prompts)

| ID | Decision | Why (defect in the first pack) | Prompts touched |
|---|---|---|---|
| D-01 | The retry for PostgreSQL 40001/40P01 wraps the WHOLE transaction (`SerializationRetryBehavior` outside `TransactionBehavior`). Handlers never manage transactions or isolation. | The first pack opened the transaction in an HTTP middleware and retried inside it: after a serialization failure the transaction is aborted (25P02), so no retry could ever succeed. It also relied on `SET LOCAL transaction_isolation` after `set_config`, which PostgreSQL rejects (isolation cannot change after the first query). And it committed after the response was written, and rolled back the refresh-token theft revocation on the 401. | P-109, P-511, P-101, P-112, P-113, P-119, P-302, P-306, P-309, P-406, P-408, P-510, P-512, P-902 |
| D-02 | Idempotency is a MediatR behavior + store INSIDE the business transaction (`INSERT ... ON CONFLICT DO NOTHING`, response stored in the same commit). | Old middleware inserted a "pending" row in the caller's own uncommitted transaction, so two concurrent identical requests collided on the primary key (HTTP 500) and could not replay; it buffered HTTP responses. | P-117, P-511, P-513, P-518, P-520, P-523 |
| D-03 | Two database roles: owner (migrations/tooling) and `storeos_app` (`NOSUPERUSER NOBYPASSRLS`) for the app. `RlsRoleGuard` blocks startup otherwise. `deploy/db/post-migrate.sql` re-applies grants and REVOKEs UPDATE/DELETE on append-only tables. | PostgreSQL never applies RLS to superusers. The compose `POSTGRES_USER` and Testcontainers' default user are superusers, so ALL tenant isolation (and all RLS tests) would have silently passed/bypassed. Plan §6.5 (no UPDATE/DELETE grant on ledgers) was not implemented anywhere. | P-002, P-101, P-107, P-108, P-111, P-1201, P-1203, P-1204 |
| D-04 | Fixed behavior order (see CONTRACTS §3) and isolation by marker interface; reports run RepeatableRead READ ONLY (one snapshot) on `ReportingDbContext`; every `*Query` must implement a marker (architecture test). Retry applies to every read-write request. | Plan says ReadCommitted for reads; multi-query reports then disagree with each other (breaks "consolidated == sum of branches"). RepeatableRead commands can also raise 40001, so retrying only checkout was not enough. | P-109, P-114, P-119, P-511 |
| D-05 | `tenants.subdomain` (unique) + `ITenantResolver`; login/manifest/logo resolve the tenant from the Host header (`apex.pos.storeos.io`, `apex.localhost` in dev). No anonymous `?tenantId=` override. | Plan §12.1 routes tenants by subdomain but the schema had no column for it; P-1008 shipped an always-null placeholder (forbidden by the pack's own anti-stub rule). | P-102, P-303, P-1008, P-1009, P-1010 |
| D-06 | Branch code is 1-3 characters `[A-Z1-9][A-Z0-9]{0,2}`. | `<BRANCH>/<FY>/<NNNNNN>` is exactly 16 characters only with a 3-char code; P-310 allowed 10, so checkout would throw on the first invoice. Rule 46(b)/e-invoice schema: max 16 chars, alphanumeric plus `/` and `-`, no leading 0. | P-102, P-206, P-310 |
| D-07 | Estimates use their own number series (`EST-<fy>`, format `<BRANCH>/E/<FY>/<NNNNNN>`). | Estimates consumed numbers from the tax-invoice series; every unconverted estimate left a gap in the "consecutive" GST series. | P-206, P-501, P-517, P-518 |
| D-08 | One `ErrorCatalog` maps error codes to HTTP status. Auth failures are 401/403 (not 422). | Status codes were patched prompt-by-prompt; auth codes fell back to 422 and would never trigger the frontend's refresh-on-401. | P-113, P-114, P-310, P-410, P-522 |
| D-09 | Pre-authentication flows (login, refresh, logout) run through `IAnonymousTenantRequest`. Refresh tokens are `<tenantId:N>.<random>`; the raw token is never stored, only its hash. Theft detection returns a flagged result (commits) instead of throwing (would roll back). | `IgnoreQueryFilters()` does not bypass RLS; the anonymous queries would return zero rows. | P-106, P-303, P-304, P-305, P-306 |
| D-10 | Application code uses `IAppDbContext` and interfaces for `JwtTokenService`, `RefreshTokenService`, `InvoiceSequenceAllocator`, `IObjectStorageService`. | 14 prompts put code in `StoreOS.Application` that used `StoreOsDbContext`/Infrastructure types: the solution would not compile (circular reference). | P-101, P-302, P-304, P-501, P-901 + 14 layering fixes |
| D-11 | Default permission sets of the five standard roles: CONTRACTS §7. | Plan marks cells "configurable" without defaults; P-1206 needs a concrete set. Conservative defaults chosen. | P-1206 |
| D-12 | `DomainException` lives in `StoreOS.Domain.Exceptions` from P-113 on (no move in P-202). P-112 and P-113 run before P-109. | P-109 needs the exception and correlation id; the move in P-202 only created churn. | P-113, P-202, INDEX |
| D-13 | New prompts: P-313 (change/reset password), P-1206 (tenant provisioning CLI). Logo is persisted (`branding.logo_key`) and served (`GET /api/tenant/logo`); exports get a concrete CSV format. | No way to change a password, create a real tenant, serve the logo referenced by the manifest, or produce the "spreadsheet" exports the requirements demand. | P-313, P-1206, P-1009, P-804, P-805 |
| D-14 | Background jobs run per tenant via `ITenantJobRunner`. | With FORCE RLS a job with no `app.tenant_id` sees zero rows: the nightly reconciliation (P-905) would report "all good" forever. | P-109, P-905, P-906 |
| D-15 | Local `dotnet-ef` tool manifest, `FrameworkReference Microsoft.AspNetCore.App` for Infrastructure, `Swashbuckle.AspNetCore` added to the package allowlist, CI e2e job fixed (owner migrate, readiness wait, app role). | Missing tooling/allowlist entries would have stopped executors at P-004/P-101/P-1001/P-1203. | P-004, P-101, P-1203 |

## Open (a human must decide; the prompts already work either way)

| ID | Question | Recommendation |
|---|---|---|
| O-01 | Invoice series format: the FY-consecutive format is the default. The daily-timestamp format (`B01-20260923-143005-007`, 23 chars) violates the 16-character limit and is not consecutive across the year. | Keep FY-consecutive; get the shop's CA to sign the choice before go-live (Plan §8.5 already requires it). |
| O-02 | GSTR-1 export mapping (B2B/B2CL/B2CS/HSN tables, treatment of margin-scheme lines and gift lines) is not specified by the plan or the requirements. P-805 exports what is stored, in a flat CSV. | Have the CA review one real month before relying on the file for filing. |
| O-03 | **Toolchain support dates.** The pack pins .NET 8 (P-003/P-004/P-005/P-1203), Angular 18 (P-006/P-007) and Node 20. Microsoft ends .NET 8 support on 10 Nov 2026 (about six weeks from today); Angular 18 has been out of support since Nov 2025; Node 20 reached end of life in April 2026. | Decide BEFORE running P-001. Recommended: .NET 10 LTS (supported to Nov 2028), a currently supported Angular major (21; 20 ends Nov 2026) and Node 22 or 24 LTS. See `TOOLCHAIN_UPGRADE.md`. If you keep the pins the pack is internally consistent and reproducible, but the production system would run unsupported. |
